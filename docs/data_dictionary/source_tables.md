# Source table dictionary (PostgreSQL operational schema)

Business definitions for the QuickCart OLTP tables created in
`infrastructure/postgres/migrations/V001__core_schema.sql`. Analytical Gold
metric definitions are added in Phase 2 (`metrics.md`).

## Conventions

- All timestamps are `TIMESTAMPTZ`, stored and generated in UTC.
- All monetary amounts are `NUMERIC(12,2)` in INR (`currency` column, default `INR`).
- IDs are `BIGINT GENERATED BY DEFAULT AS IDENTITY`; the simulator assigns explicit
  deterministic IDs.
- Status fields are CHECK-constrained enums; lifecycle diagrams below list allowed values.

## Entity tables

### stores
One row per dark store. `store_code` is the stable external identifier (`STORE-001`…).
`service_radius_km` bounds the delivery catchment; `opened_at`/`is_active` give lifetime.

### customers / customer_addresses
`customers` is deliberately PII-free (no names/phones) per kit/04 §2 — only a stable
`customer_code`. Addresses carry city, postal code and geo coordinates; `is_default`
marks the primary address; `valid_from`/`valid_to` exist now and become the SCD2
learning source in Phase 5.

### products / product_prices
`products`: catalog with category/subcategory/brand and explicit selling unit
(`unit_size` + `unit_name`, e.g. 500 g). `product_prices` holds `mrp` and
`selling_price`; `store_id NULL` means a global price. `valid_from`/`valid_to` are the
price SCD2 learning source.

### riders
`home_store_id` anchors the rider; `shift_start`/`shift_end` (TIME) define availability
windows; `status` ∈ {AVAILABLE, BUSY, OFFLINE} (end-of-history snapshot: OFFLINE).

### promotions
`promotion_type` ∈ {PERCENT_OFF, FLAT_OFF, FREE_DELIVERY}; `value` meaning depends on
type (percent, flat amount, or 0 for free delivery). `min_order_value`/`max_discount`
bound applicability. `is_active` reflects whether the window is live at seed end.

## Transactional tables

### orders
Monetary reconciliation rule (enforced by generator and `db.validate`):

```
total_amount = subtotal − item_discount − promo_discount + delivery_fee + tax_amount
```

`status` lifecycle: CREATED → PLACED → PAYMENT_PENDING → PAID → ACCEPTED → PICKING →
PACKED → RIDER_ASSIGNED → OUT_FOR_DELIVERY → DELIVERED; terminal side paths CANCELLED,
REFUNDED. Not every order passes through every state.

### order_items
`quantity > 0`; `line_total = quantity × unit_price − line_discount`. Every order has at
least one item (unserved stockout demand is never materialized as an order).

### payments
One row per payment attempt. `status` ∈ {INITIATED, AUTHORIZED, CAPTURED, FAILED,
REFUNDED}; `attempt_number` increments per retry; `failure_code` set on FAILED.
Rule: a captured first attempt equals `orders.total_amount` (kit/02 §9).

### deliveries
One row per order that reached fulfillment (payment-canceled orders have none).
Lifecycle: `assigned_at` ≥ order `placed_at`; `picked_up_at` ≥ `assigned_at`;
`delivered_at` ≥ `picked_up_at`; CANCELLED rows set `cancelled_at` and leave delivery
timestamps NULL. `promised_by` = placed_at + store SLA (25–40 min); lateness is derived
from `delivered_at` vs `promised_by`, never stored as a label.

### inventory / inventory_movements
`inventory` is the current snapshot per (store, product): `on_hand_qty`,
`reserved_qty`, `reorder_point`. Movements are the immutable history:
`movement_type` ∈ {RECEIPT, ORDER_RESERVE, ORDER_RELEASE, SALE, MANUAL_ADJUSTMENT,
TRANSFER_IN, TRANSFER_OUT, DAMAGE}; `quantity_delta` is signed (SALE is negative);
`reference_type`/`reference_id` point at the cause (ORDER → order_id, AUTO_RESTOCK).

### support_tickets
Derived from operational friction: LATE_DELIVERY, ORDER_CANCELLED, PAYMENT_ISSUE,
REFUND_REQUEST. `priority` ∈ {LOW, MEDIUM, HIGH, URGENT}; `status` ∈ {OPEN,
IN_PROGRESS, RESOLVED, CLOSED}.
